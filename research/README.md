# Research boundary

Keep the existing `fyp-data-refinement` project intact during the initial application setup. It contains research history and artifact producers, not a set of files to delete because the web app now exists.

Use the inventory in `docs/ARCHITECTURE.md` to record each notebook/script's inputs, outputs, execution order and purpose. Add links/paths and versions here after inspecting the actual project. This starter does not bundle or claim to have audited the complete research source.

Training and exploratory notebooks remain research work. Reusable monthly validation, feature engineering, scoring and explanation code can be extracted into application services later, with equivalent-output checks. Keep raw/synthetic source tables and exported results out of the code repository unless intentionally versioned through a separate data/artifact mechanism.
